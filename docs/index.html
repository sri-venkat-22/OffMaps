    What each part buys

    Every stage adds one component to the loop, and every stage drives the same outages. Median drift, as a % of distance driven without GNSS, averaged over 10, 30, 60 and 120 s outages.

    The train-drive figures come from drives run with models that never saw them, but the last two stages were tuned on those drives, so they are somewhat optimistic. The validation set is too small (about an hour) to separate the last three stages. Full tables: out/ablation/ablation.md.

    Where it stands

    Not under 10 % yet

    The PS target is drift below 10 % of distance. The app reaches 11.7 % on train drives it never saw and 16.4 % on the held-out test drives, which were scored once, before road matching shipped.

    Speed is the gap

    At the end of an outage most of the error lies along the road, not across it. The gyro keeps the heading; what drifts is the distance. The next step is training data from the target phone, rigidly mounted.

    It runs on a phone

    Native Android app with a C++ core, the AI speed model on-device and an offline map of Hyderabad. It is live on a Redmi Note 9 Pro; this page replays the same loop on real recorded drives.

    How the loop runs

    1. Every sensor sample The gyroscope turns the heading; the filter predicts position.
    2. Every second SpeedNet reads speed from vibration; the fusion head decides how far to trust it.
    3. Every fix GNSS corrects the filter, weighted by how trustworthy the fix looks. There is no mode switch.
    4. During an outage An HMM matches the estimate to the road network and pins it across the road.
